Component Design Patterns

8 architectural solutions in one place

1. Computational

Stateless input/output function. The simplest form of component.

2. Plugin

Dynamically select implementation (v2) based on configuration.

-

3. Stateful

Persist state between calls (AtomicU32 counter).

-

4. Policy-Controlled

Access resources only through explicit Capabilities (fs:read).

-

5. Resource

Manage lifecycle of an object (open/read/close) via handles.

-

6. Pipeline

Chain components (A → B) where output of one is input of another.

-

7. Replaceable

Hot-swap component version without restarting the server.

-

8. Untrusted Extension

Validate manifest (Admission Control) before loading third-party code.
